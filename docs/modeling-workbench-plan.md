# Houdini Modeling Workbench — research and implementation plan

**Recommendation:** build a viewport-first authoring layer over ordinary SOP graphs. Persist *what to edit* separately from *how to edit it*. Use native geometry kernels where they meet the contract; bring in custom geometry code only where a measured gap warrants it. The first deliverable is not another modeling shelf: it's a Grab that still grabs the same bicep after remeshing, and refuses when it cannot tell which surface is the bicep. Pair it with Extrude → Bevel to prove the same architecture handles generated topology, not just deformation.

### Local probes (Houdini 22.0.466, headless `hython`, in-memory test geometry)

- `polyextrude::2.0`, `polybevel::3.0`, `polyfill`, `boolean::2.0`, `smooth::2.0`, `groupfindpath`, `vdbsmoothsdf` exposed verbs. `polybridge`, `edit`, and `sculpt::2.0` did not in this probe. Look up by the actual node type; the short name is not always a verb alias. The PolyFill node exposes `perfectgrid`, but its verb did not accept it; test node/verb parameter and output parity rather than inferring it from the node UI or help header.
- PolyFill grid mode (`fillmode=5`) on planar 8- and 12-edge annulus holes produced 4 and 9 patch quads respectively. The 7-edge hole produced **no patch**, not an automatic repair or an alternate fill. Verify the output group and report failure. With a fixed boundary, an all-quad patch requires an even edge count (internal edges are counted twice in the face-side sum); even is not sufficient for a well-shaped rectangular grid.
- Extruding a single face with primitive `feature_id=42` copied `42` onto the cap **and all four side faces**. An inherited attribute is not unique lineage. Generate public roles from validated output groups and don't pass user `id` off as unique unless the upstream contract establishes that.

## Product design: edit the model without living in the network editor

1. Pick or hover a point/edge/face in a SOP viewport. Select a command from a small radial, shelf or searchable action menu. The menu follows selection type (a boundary gets Fill/Bridge; faces get Extrude/Inset; edges get Bevel). Support normal Houdini selection and snapping. An empty or invalid selection never means 'entire mesh'; whole input is an explicit action.
2. Drag directly, type an exact amount, or use a handle. Show distance/radius/profile and snap state on the HUD; avoid modifier puzzles. Use wheel for divisions or radius only in the active gesture; don't take over normal viewport navigation. Start with one primary drag control per tool; alternate settings stay visible in a compact HUD/parameter strip. Keep pivot/frame and selection across operations where valid. Preview generated cap/side/patch so it's clear what will be selected next.
3. Release to commit a gesture, Esc to cancel an in-progress gesture; tools needing multiple picks preview until accepted. One completed gesture = one undo. Expose the last action's settings without introducing a second history. Quick repeat copies parameter settings onto a **new** target, never the previous target. Handle pane switches, interruption, exceptions, node deletion and undo during hover without leaving a scratch node or stuck undo block.
4. After an upstream change, show the affected target and the reason for a failure on the operation. **Rebind** overlays saved hints and current candidates; one click or reselect replaces the target in the existing node, preserves its settings and operation identity, and is undoable. **Freeze** is explicit and labeled exact-only; never silently revert to a stale mesh. Keep native SOPs available for edits that cannot be expressed robustly.

## Data model and evaluation

**Architecture choice.** A shelf-only wrapper is cheap but leaves raw selections and recook failures untouched. A single bespoke editable mesh or modifier stack can make gestures fast but duplicates Houdini's graph, makes branches/reordering harder, and risks stashing geometry. A universal remap service is attractive but cannot infer intent for arbitrary replacement meshes. The SOP-based design keeps the native graph, with a bounded resolver doing only the work each operation asks for. A branch can consume an authored point/guide without sharing the UI that produced it.

- Package as namespaced SOP assets and a shared Python viewer/tool layer; no alternate scene format or required open panel. One semantic operation per operation node initially. A multi-stamp brush gesture is one operation, not a chain of SOPs per mouse event. Group edits visually into bands/network boxes; don't invent a second hidden stack in v1. If long stacks become pathological, prototype a brush-layer asset that batches consecutive compatible strokes with checkpoints; require evidence before introducing it.
- Asset parameters: operation UUID (independent of node path), payload schema/version, typed `TargetSpec`, editable operator parameters. Duplicate/copy workflows must assign new UUIDs to copied producers and remap copied local dependents where appropriate; reject duplicate keys at resolve time. Houdini input wiring points at the current mesh (and optional guide/reference input); no reliance on scene node paths in target payloads. Use one variant-specific payload rather than a serialized mesh per edit. Compact guide points or strokes can be explicit side input geometry if useful; cook must work in `hython` with no state loaded. Upgrades migrate versions explicitly; viewer code never quietly rewrites target evidence on recook.
- `TargetSpec`: typed domain (point, edge, region, boundary, feature role, or placement); source contract and scope (e.g. explicit `part=left_arm` attribute value or operation UUID and role); optional seeds, local or rest frame and normal, radius/extent, method, features to exclude, and expectations such as component/loop count, coverage, orientation, and assignment cardinality. Data belongs in SOP-local/guide coordinates, not camera or world coordinates unless that is the intentional placement mode. A tangent is authorable (guide direction or captured axis projected into the tangent plane); a normal by itself cannot define roll. Persist sample distances and tolerances relative to a known part/feature scale plus absolute cap; avoid global scene-size tolerance.
- A resolver produces a **current** point/primitive/edge group or weights/frame, plus a typed report. Only the adapter can hand component numbers to a kernel; those numbers are transient. Use a private namespace with collision checks, do not rewrite `id`, `name`, UVs, materials or unrelated groups. Keep public roles as minimal primitive attributes/groups as appropriate; edge roles need Houdini edge groups or explicit feature curves, not implied labels on two endpoint points. Record granularity: one cap *region* may include many faces. Do not export full ancestry lists per face or assume arbitrary third-party SOPs preserve roles; adapters can explicitly carry or invalidate known metadata.

### Resolver policies (not a blind fallback chain)

| Policy | Resolution and bounds |
|---|---|
| **By feature / rule** | Query current named group, scoped attribute, feature/role (e.g. `boss_extrude.cap`, `boss_extrude.rim`), geometric predicate, or guide frame. Validate producer, domain, connectivity and expected cardinality. Roles may survive subdivision if preserved/rebuilt; a role becoming two disconnected caps is not necessarily the same region. A feature-oriented bevel can explicitly mean 'current sharp edges of this boss rim', not 'edges 20–27'. |
| **Exact** | Use verified persistent unique IDs where an upstream producer warrants them, or an ordered-connectivity and source-identity check plus component numbers explicitly labeled topology-locked. An ordered-connectivity hash alone cannot prove identity under symmetric reorder/replacement; require a verified source/order contract, and reject when that evidence is absent. Don't synthesize IDs each cook and count those as stable. |
| **Spatial / anchored** | Within a stable part/guide frame, project sparse seeds onto eligible current primitives; test signed normal/orientation and distance, reject unrelated or opposite sheets. Generate multiple candidates (not just raw nearest point); score position, normal, scope, seed agreement and region/loop signature; compare the best and next *distinct surface regions*, not neighboring triangles of one region. Use deterministic traversal/ties for display, not to silently choose between plausible targets. Budget via a reusable BVH and bounded search. No automatic scene-wide search after scope disappears. |

Release v1 with **explicit scope + guided/current local projection**, not arbitrary correspondence tracking. A clean named cap selection stays a rule. A paint/Grab intent stays a field. A single selected point or an irregular hard-face selection may just be exact-only; explain that at capture. Later add sampled region boundaries and interior/exterior evidence, then connected regrowth of a hard face region. Don't infer hard topology by transferring a soft weight above a magic threshold. If a former face boundary now runs through unaligned faces, warn or explicitly change the operation to create a cut; do not enlarge the selection silently. Edge loops need orientation, seam/chain structure and landmarks, not proximity of individual edges.

**Failure policy:** `Resolved`, `Reprojected`, `Needs rebind`, `Unsupported` (or explicit Disabled). Good reprojections can run and be surfaced on demand; uncertain/partial reprojections are not applied by default. Failure passes current upstream mesh unchanged with a persistent SOP warning, no generated outputs from this operation, and a structured failure status so declared dependents cannot accidentally act on an empty group. Independent edits may continue; publishing/export can opt into strict error mode. Never emit the last good geometry in place of current input. Reports should provide the failed condition (missing scope, multiple eligible sheets, invalid loop, unsupported transfer, etc.); the UI can show an ephemeral ghost target and current candidates.

### The bicep case, end to end

Author a `left_arm` scope and a shoulder-to-elbow guide (or use a stable procedural local frame). Pick center on the bicep; record position in that frame, outward normal/tangent, radius, curve of falloff and a radial scale or grab vector in the authored frame. Project onto the arm only, then seed graph distances from the hit's face vertices using within-face distances. Grow on connected mesh within the radius (optionally across neither creases nor group boundaries); map distance through a smooth compact falloff. Freeze this weight field while dragging on the current input. Re-evaluate the same field on each upstream input at cook; point and primitive numbers may change completely. A new resolution with a recognizable surface should work; a rotated arm follows only if the guide/transport carries the intended frame. A removed arm, duplicated overlapping sleeve within scope, or remesher that destroys the scope/frame must stop or ask for a rebind when the evidence no longer suffices. This is not semantic recognition of anatomy.

For coarse meshes the edge path distance is approximate and anisotropic; compare with an object-space radius clipped by connected region/crease tests, especially when radius spans only a few edges. Graph traversal must stop at radius, not walk the entire connected character. Test close folded skin and touching shells, not just separate boxes. Add approximate heat distance only if visible anisotropy persists and factorization/rebuild cost fits the budget. Use stable substeps/sampled weights for Inflate and Smooth; store a compact arc-length-resampled stroke with pressure/strength where needed, not mouse events or per-point deltas. Set sample spacing in relation to radius, and define order and preview/final parity explicitly. Grab itself should store a single anchor and final transform. Fixed-topology HDAs may offer native Sculpt separately for high-frequency details; no dynamic topology, elastic PDE or high-poly sculpt goal for v1.

## Operation plan

| Command | First viable kernel + behavior | Guardrail / extension |
|---|---|---|
| Move/Rotate/Scale, Grab | Native handle or screen/axis/normal drag; common weighted transform `P' = P + w(P_transformed - P)` (computed from gesture-start input), local-space displacement. Rigid transforms use verified region/group; optional proportional falloff. | Preserve boundaries/creases via masks. Add mirrored anchors with explicit mirror frame, dedup on seam and no accidental double application; live symmetry can follow after the basic state is reliable. |
| Extrude / Inset | Native PolyExtrude; separate UX, explicit region vs individual defaults, numeric distance/thickness, cap/rim/sides roles. Start with planar or well-conditioned regions; keep cap selected to chain. | For Inset test uniform-width and corner behavior, concavities, holes and nonplanarity. Detect collapse/inversions or overlap where feasible; preview a clamp or refuse, never claim all regions support a clean constant-width inset. No silent collapse/auto-weld. |
| Bevel | Native PolyBevel with profile, width/segments and explicit width mode; use feature edge group or rule. Preview corner behavior and intersections; allow width reduction with requested vs actual displayed. | Test high-valence junctions, concave corners, adjacent small edges and non-manifold input; don't globally bevel newly counted edges when a feature disappears. |
| Fill / Grid Fill / Bridge | PolyFill/PolyBridge where applicable; adapter extracts ordered boundary, validates degree-2 single cycle for single-hole Grid Fill, no repeated edges, and explicit multi-loop mode. Expose corner/rotation and dimensions/span if kernel permits. Explicit triangle/fan option for irregular holes. | Initially support even, compatible grid boundaries and check output group, winding, pinning and patch quality. If the native grid cannot deliver requested span/flow, prototype four anchored sides with equal opposite edge counts, transfinite/Coons interpolation and constrained relaxation/projection. Odd/unequal layouts need explicit boundary splits, poles, or triangles, never implicit changes to the rest of the mesh. |
| Smooth / Relax / Inflate | Smooth SOP on `P` only with selection/feature pinning and weight mask; compare curvature- and scale-dominant modes. Brush uses same resolver/weights and explicit mask. | Place Point / Shape | Click construction plane, snap feature, or pick surface; show ghost preview and frame, drag size, optionally numeric offset and roll. Store plane coordinates or anchor+frame. | Loop/slide, dissolve, weld | Fill out direct modeling after the core: reproducible loop rules with Group Find Path where useful, native kernel adapters plus operation postconditions. | Weld is intentional, not a side effect of every move; where there is no reliable rule offer a guarded exact operation. |

### Rounded Boolean: two explicit products, not two hidden fallbacks

**Mesh-preserving mode (default for box/hard-surface work).** Keep operand B live on its own branch. Preflight solidness, orientation, thin sections and overlap/tangency; use native Boolean and extract seam/affected faces. Try seam bevel on valid loops first, with quality checks. If native bevel is insufficient, research a *local* seam-strip replacement: protect outer rails, match sampling with explicit splits where necessary, bridge/relax/project strip, carry face roles and attribute interpolation rules; preserve outside of the changed band. Complex seam networks, grazing contacts and densely repeated cutters may not support this. Deliver sharp Boolean explicitly or refuse rounded mode; do not ship automatic whole-mesh remesh as an invisible cleanup.

**Clay blend mode (explicit topology replacement).** Use aligned narrow-band VDB SDFs for closed operands, CSG plus controlled masked smoothing or a smooth SDF blend if tested; convert back to polygons. Radius, voxel size, minimum wall/feature size, pad/band and voxel/memory budget must be visible. Preview at a lower bounded resolution and label it; validate at final resolution. Conservative voxel-size/scale ratios are starting heuristics, not a guarantee of topology or blend radius. Transfer attributes only by explicit policy (e.g. source-region-aware material transfer); warn which roles, seams or UVs do not survive. VDB output is a clean shape candidate, not an editable quad cage. Local remeshing + stitching is a separate experiment, not a promise that voxelization preserves distant topology.

**Quality gate:** no new non-manifold edges or bow-tie vertices in supported closed solids; check degenerates, inverted strips, seam self-intersections, slivers, expected shell count and wall thickness on fixtures; compare boundary connectivity and attributes outside declared footprint for mesh mode. Distinguish inherited defects from introduced ones. Use PolyDoctor diagnostically, not as an unconditionally destructive cleanup step. For sub-D assets also review silhouette and highlight flow under subdivision; manifold triangles alone do not pass that bar. Run cheap topology checks on commit; expensive self-intersection and thickness checks may be scoped or on-demand, with unchecked cases labeled. Compare with Modeler's Soft Boolean workflow where available; its product claims are not our topology contract.

## Runtime and UX constraints

- **Authoring** in Python HOM/viewer states; **cooking** through compiled native SOPs, VEX for simple per-element math and compact metadata. Prototype resolver in Python only to establish behavior; keep per-point loops and Python geometry copies out of the gesture hot path. Bounded graph search needs a proper queue/adjacency implementation; benchmark native graph tools or a lightweight VEX/native prototype, and consider HDK only if profiling shows it is the bottleneck (and budget builds per Houdini version). Don't assume verbs are always faster: compare actual node cooks, graph wiring overhead, geometry copying and viewport upload.
- Use one scratch preview per pane/gesture, coalesce events to latest (main thread for HOM/UI), and snapshot camera/input/generation. Don't recook the downstream graph continuously. Try drawable/handle-only feedback for cheap low-latency effects; full-resolution connected preview where necessary and within budget. No background thread touching HOM. If input changes mid-gesture, invalidate preview and abort/restart rather than commit stale picks. Catch interrupt/cancel paths and close undo exactly once. Preview result never changes canonical data until commit; commit cooks real full-quality output and gates on validation.
- Reuse BVH/adjacency/sparse influence per current input revision; adjacency depends on connectivity, geometric distances/BVH/refits on positions and frame, masks on relevant attributes/groups. Cache keyed by those dependencies + operation params, with bounded per-pane/per-network memory and eviction, not a global retained geometry list. Avoid hashing the whole mesh every mouse event; if source change cannot be tracked reliably, conservatively rebuild at gesture boundary. Aim for `O(V+E)` shared topology storage and `O(K)` local weights for K affected points; persistent payload `O(stroke samples + landmarks)` per op. Engine may still need `O(V+F)` output work/memory per cook; measure Houdini SOP cache footprint on long chains before trading the visible graph for a layer. No implicit per-op snapshots except explicit bake/checkpoint.
- Initial **targets, not measurements**, on this workstation: 50k-point moderate mesh warm Grab/transform p95 input-to-visible update ≤33 ms; ~200k-point target ≤50 ms on a localized drag or degrade explicitly. Warm p95 picking/hover callback ≤8 ms excluding redraw; simple-op commit p95 ≤150 ms at 50k points without unrelated downstream work. Topology-changing preview ≥20 Hz on agreed 50k fixtures or use coarser/local preview; for expensive Boolean release-to-result initially benchmark separately with progress/cancel and voxel cap. Track cold vs warm resolve/kernel/validation/upload times, cook count, peak RSS and `.hip` growth across 100/500 edits with identical baselines. Example payload gate: 100 single-anchor edits add <100 KB of uncompressed authored payload (not whole `.hip`/SOP cache). Measure input-to-display only with GUI instrumentation, not `hython` timing. Compare same view/render mode against native tools and installed Modeler where runnable.

## Milestones and exit criteria (modeling only)

1. **Spikes and fixtures.** Extract testable native adapters and validate node/verb differences on target builds. Create procedurally generated fixtures: tagged arm (remesh/pose variants and a sleeve), hard-surface panel/boss nested feature chain, 7/8/12-edge planar and skewed openings, thin-walled solids and tangent cutters. Capture baseline interaction recordings/metrics on a hidden desktop via repo test process conventions; offline only. Add no runtime dependency on Modeler. Go/no-go: prove headless cook and usable preview for one shape modification.
2. **Two vertical slices.** Build scoped projected Grab and generated-role Extrude → Bevel, with SOP/UI boundary, cancel, one-step undo, preview and repair. Test renumbering while preserving labels, stable deformation with a guide, density changes with preserved/rebuilt scope, topology splits and deleted/upstream replaced sources. Reprojections judged against authored masks/landmarks on a common sampled surface (coverage and leakage), not matching vertex counts. Symmetric ambiguity, flipped normals, missing scope, empty selections and duplicate producer identity must not silently apply. Golden scene save/reopen and headless cook must agree with viewport commit. Instrument p95 and memory. If scoped reprojection is unreliable, restrict to explicit guide+region bindings before adding further tools.
3. **Everyday kit.** Add Inset, exact/weighted transform, Smooth/Inflate, Point/Shape, Grid Fill/Bridge, snapping/pivots and the contextual action surface. Build a compact comparison script: cut/raise a panel and bevel it, grid-cap a hole, reshape a bicep, place a cutter, change source density and repair one failed selection. Record time, clicks, pointer travel/number of pane switches, unintended edits and undo count against native/Modeler baseline; prioritize removing friction over adding shortcuts. Test camera projection, transformed objects, multi-pane focus, state interruption, session round-trip and missing HDA/version behavior. Continue conventional operations (slide, split, weld, symmetry) after these workflows feel good.
4. **Rounded joins.** Compare mesh Boolean + seam bevel against VDB on shared fixtures and separate result classes. Deliver a supported subset with refusal diagnostics; prototype strip replacement only if needed for reference models and if untouched topology/attributes can be maintained. Test downstream reference behavior when Boolean removes or replaces a feature.
5. **Scale and release.** Long-stack profiling, failure UI, schema migrations/copy-paste behavior, documentation for the robustness classes, before/after demos and optional runtime key audit. Optimize measured hotspots instead of rewriting the geometry stack in C++ first. Keep a compact seam/feature/reference metadata contract for future retopo and UV tools; no retopo/unwrap implementation in these milestones.

For the resolver benchmark, give each fixture an expected result class and sample the original and edited surfaces in a shared guide frame. Report target acceptance/abstention separately from wrong accepts. For the bicep, measure support overlap, area-weighted displacement error and peak leakage onto the torso/sleeve; for a feature role, compare connected cap/rim identity and confirm the bevel only modifies its declared footprint. Add scale and winding variants, shuffle point and primitive numbering independently, and include a symmetric pair whose candidate score separation approaches zero. Tune tolerances on one fixture family, then hold out another to detect overfitting. Test unchanged pass-through on failure, not just the presence of a warning.

The central acceptance criterion is **zero silent wrong-target edits on the adversarial fixtures**, not maximum automatic rebinding. The product should make it easy to author a durable reference, show what it resolved to, and make the uncommon repair cheaper than rebuilding the edit.
